# Dev Crew AI Ideal Customer Profiles

## ICP 1: AI-native solo developer / open-source maintainer

### Profile

- Maintains one or more repos.
- Uses GitHub issues and PRs.
- Experiments with Claude Code, Copilot, Codex, OpenCode, Aider, Ollama, Hermes, or custom local tools.
- Wants to move faster without losing control.

### Pain

- One agent session at a time is too slow.
- Branch switching loses context.
- Agent changes are hard to review.
- Parallel agent work feels unsafe.

### Desired outcome

Run multiple coding sessions in parallel while keeping every task isolated, visible, and reviewable.

## ICP 2: Local-first builder

### Profile

- Works on prototypes, side projects, zipped apps, local-only experiments, or private client folders.
- May not have Git initialized.
- May not want to publish to GitHub.

### Pain

- AI changes are risky without version control.
- Git setup feels like friction.
- GitHub is too much overhead for early experiments.

### Desired outcome

Open a folder, initialize local Git safely, create a lane, run an agent, and review changes locally.

## ICP 3: Small engineering team / startup

### Profile

- 2–20 engineers.
- Uses GitHub.
- Wants agents in the workflow but needs guardrails.

### Pain

- Agent output is not auditable.
- Multiple agent sessions are hard to coordinate.
- Generated PRs need policies and review expectations.

### Desired outcome

A standard way to turn backlog items into safe, reviewable agent work lanes.

## ICP 4: Enterprise power user

### Profile

- Developer in a larger organization.
- Security/privacy constraints.
- Approved providers may vary.

### Pain

- Cannot rely on random hosted agent SaaS.
- Needs local-first workflows and visible commands.

### Desired outcome

Bring approved providers and run locally with clear audit boundaries.
