## Problem Section

### AI coding is still too sequential

You can ask an agent to fix a bug, write docs, review a PR, or build a feature — but most workflows still happen in one terminal, one branch, and one context at a time.

That breaks down when you want to run several useful coding agents in parallel.

Common pain:

- one agent blocks the next;
- parallel edits collide silently;
- GitHub-first workflows exclude local/private projects;
- terminal output gets messy fast;
- developers cannot easily see lane status, diffs, branch names, or provider activity.

## Solution Section

### A visual command center for your dev crew

Dev Crew AI turns work into visible lanes. Each lane can have its own branch, worktree, task, provider, and terminal pane.

Use it with:

- GitHub repositories;
- local Git repositories;
- plain folders that need safe local Git initialization.

Bring your own agent:

- Claude Code;
- GitHub Copilot;
- Codex;
- OpenCode;
- Aider;
- Ollama;
- Hermes;
- custom commands.

## Feature Blocks

### Local-first projects

Start with a GitHub repo, local Git repo, or plain folder. Dev Crew AI can initialize local Git before agent work begins so changes are trackable and reversible.

### Multi-terminal agent panes

Run separate agents in separate panes. Add a pane, move it left/right/top/bottom, and keep each lane visible.

### Worktree safety

When Git is available, each lane can work in an isolated worktree and branch so parallel tasks are easier to review.

### Message bus coordination

Agents and users coordinate through an auditable message bus instead of hidden shared context.

### GitHub optional

GitHub issues, PRs, and CI are powerful — but Dev Crew AI should still be useful before a project is published.
