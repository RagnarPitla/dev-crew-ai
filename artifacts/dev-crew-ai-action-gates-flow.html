Action Gates

PM Spec → Dev → QA → PM Final → Push.

Action Gates make GitHub push status visible. Work cannot move to public shipping until evidence exists and PM Final approves it.

Dev Crew AIRBuild.aiNo hidden push
1

PM Spec

Define problem, scope, acceptance criteria, target files, and non-goals.

2

Dev

Use TDD, implement the smallest working slice, and capture build output.

3

QA

Review evidence, run tests, check secrets/private files, and verify claims.

4

PM Final

Approve or block GitHub push with visible status.

Outcome: GitHub push is a visible product state, not a hidden developer habit.
